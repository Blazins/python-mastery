Chapter One

Pricing a Product Feed

A supplier sends you a spreadsheet of raw product data every morning. Before any of it can go on a storefront, someone has to turn a cost, a weight, and a tax rate into a price a customer can actually be charged. That "someone" is a program — and everything a program does with data starts with values, types, and names.

Why this chapter exists

Almost every program a working developer writes is, underneath, the same shape: take some data in, do arithmetic and rearrangement on it, produce something a human or another system can use. An invoicing service turns line items into a total. A logistics tool turns package dimensions into a shipping band. A reporting job turns yesterday's raw numbers into a summary.

Before any of that is possible, you need three things that this chapter is entirely about:

  • Values — the actual pieces of data: the number 4.99, the text "Blue Mug".
  • Types — what kind of thing each value is, because 4.99 and "4.99" behave completely differently and confusing them is one of the most common real bugs in production code.
  • Names — labels you attach to values so you can refer to them later without repeating them.

The running problem for this chapter: a supplier feed gives us a product's wholesale cost, its weight, and a tax rate. We need to produce a retail price and a formatted line of text describing it. By the end you will be able to write that program from nothing.

1. Running a Python program

A Python program is a plain text file whose name ends in .py. There is nothing special about the file itself — you could write it in any editor. You will write yours in micro.

To create and open a file, in your terminal:

$ micro pricing.py

That opens an editor. Type your program, press Ctrl+S to save, Ctrl+Q to quit. Then run the file by handing it to the Python interpreter:

$ python3 pricing.py

The word python3 here is the name of a program installed on your machine — the interpreter. Its job is to read your file one line at a time, top to bottom, and carry out each instruction. pricing.py is the argument you are handing it: the file to read.

On reading top to bottom This "one line at a time, top to bottom" behaviour is worth taking literally. Python does not scan ahead. If line 5 uses something that only gets created on line 9, line 5 fails — even though the thing exists "somewhere in the file". Several of the errors later in this chapter are exactly this.

2. Values and the print function

A value is a single piece of data. 7 is a value. "Blue Mug" is a value. When Python reads your file and encounters a value, it creates that value in memory — but by default it does not show you anything. A program that consists of only the line 7 runs perfectly, produces no output, and ends.

To actually see something, you use print.

Definition

print(...) is a built-in function — "built-in" meaning it is always available, with no setup, in every Python program; you never have to fetch it from anywhere. Its job is to take the values you hand it, convert each to a human-readable text form, and write that text to standard output (which, when you run a program in a terminal, means: display it on the screen). It then writes a newline character, so the next print starts on a fresh line.

The parentheses ( and ) are how you call a function in Python — that is, how you actually make it run. The things you write between them are the arguments: the values you are handing to the function to work on.

print(7)
print("Blue Mug")
7 Blue Mug

If you hand print more than one argument, separated by commas, it prints them all on one line with a single space between each:

print("Blue Mug", 7, 4.99)
Blue Mug 7 4.99

Notice the quotation marks are not in the output. That is the point: the quotes are how you tell Python "this is text", they are not part of the text itself.

3. Types: what kind of thing a value is

Every value in Python has a type. The type determines what you are allowed to do with the value and what those operations mean. This chapter uses five.

TypeWrittenRepresentsExample from the feed
int7, -3, 0A whole number, with no fractional part. Exact, and unlimited in size.Units in stock
float4.99, -0.5, 2.0A number with a decimal point. Stored approximately (see §7).Wholesale cost
str"Blue Mug"Text. Short for "string" — a string of characters.Product name
boolTrue, FalseA truth value. Exactly two of them exist.Is it discontinued?
NoneTypeNoneThe deliberate absence of a value.A weight the supplier left blank

Two of these need immediate comment, because both are places beginners lose hours.

2 and 2.0 are different values

2 is an int. 2.0 is a float. They represent the same quantity, and comparing them will say they are equal, but they are not the same kind of object and they do not always behave the same way. A quantity of stock is naturally an int — you cannot have 2.5 mugs in a warehouse. A price is naturally a float.

4.99 and "4.99" are entirely different things

4.99 is a number you can do arithmetic with. "4.99" is a piece of text that happens to contain digit characters, and Python will not do arithmetic with it. This distinction is the single most common source of real bugs when reading data from files, spreadsheets, or web forms — because everything arriving from those sources arrives as text, even when it looks like a number. §8 is about converting between them.

Asking Python what type something is

Definition

type(x) is a built-in function that takes one value x and returns the type of that value. Printing the result shows it in the form <class 'int'>. It is a diagnostic tool — you use it when you are unsure what you are actually holding.

print(type(7))
print(type(4.99))
print(type("4.99"))
print(type(True))
print(type(None))
<class 'int'> <class 'float'> <class 'str'> <class 'bool'> <class 'NoneType'>

Note what happened in the third line: type("4.99") reports str, not float. Python does not look inside the quotes and think "ah, that's really a number". Quotes mean text, full stop.

The word "class" Python prints <class 'int'> rather than just int because in Python a type is a class — the same concept you will meet properly when you start building your own types. For now, read <class 'int'> as simply "the int type", and know the word will be explained fully later rather than assumed.

4. Names: labelling a value so you can use it again

Writing 4.99 into a calculation directly works, but it is unusable at scale — if that cost appears in six places and changes, you have six edits and a bug waiting in whichever one you miss. Instead you give the value a name.

wholesale_cost = 4.99

Read this from right to left, because that is the order Python does it in:

  1. Python evaluates the thing on the right of the =, producing the value 4.99 in memory.
  2. Python then makes the name wholesale_cost refer to that value.
Definition

Assignment — the statement name = value — binds a name to a value. The = symbol is not the equals sign of mathematics; it does not assert that two things are equal. It is an instruction: "make this name refer to this value." (The mathematical "are these equal?" question is asked with ==, which arrives in the next chapter.)

The critical mental model — and the one that prevents a whole family of confusions later — is that a name is a label attached to a value, not a box containing it. The value lives in memory; the name is a tag pointing at it.

Because of this, assigning one name to another does not duplicate anything:

wholesale_cost = 4.99
base_price = wholesale_cost   # base_price now labels the SAME 4.99

print(wholesale_cost, base_price)
4.99 4.99

Rebinding

A name can be pointed at a different value later. This is called rebinding, and it does not change the original value — it moves the label.

wholesale_cost = 4.99
base_price     = wholesale_cost
wholesale_cost = 5.49        # the label moves to a new object

print(wholesale_cost)
print(base_price)
5.49 4.99

This surprises people. base_price did not follow wholesale_cost to the new value, because base_price was never attached to wholesale_cost — it was attached to the object 4.99, and that object did not change.

Step through it

Naming rules and conventions

The rules — break these and the program will not run:

  • A name may contain letters, digits, and underscores.
  • A name may not start with a digit. 2nd_price is a syntax error.
  • A name may not contain spaces or hyphens. wholesale cost and wholesale-cost are both invalid (the second is read as subtraction).
  • Names are case-sensitive: cost and Cost are two different names.
  • You cannot use a word Python has reserved for itself, such as if, for, class, None, True.

The conventions — break these and the program runs, but reviewers will (correctly) object:

  • Use snake_case: all lowercase, words separated by underscores. wholesale_cost, not wholesaleCost or WholesaleCost.
  • Names should describe the thing, not its type: weight_kg, not float_1. Where units matter, put them in the name — weight_kg and weight_g have prevented a great many real incidents.
  • Avoid single letters except where genuinely conventional. c = 4.99 tells a future reader nothing.

5. Comments

A # character means "ignore the rest of this line". Python skips it entirely; it exists purely for humans.

# Supplier feed sends cost excluding tax.
wholesale_cost = 4.99   # GBP, ex-VAT

Good comments explain why, not what. # set cost to 4.99 is worthless — the code already says that. # GBP, ex-VAT is valuable, because that fact appears nowhere in the code and getting it wrong produces a wrong price.

6. Arithmetic

Python's arithmetic operators — symbols that combine two values into a new one:

OperatorNameExampleResultResult type
+Addition7 + 29int
-Subtraction7 - 25int
*Multiplication7 * 214int
/True division7 / 23.5float, always
//Floor division7 // 23int (if both are int)
%Modulo (remainder)7 % 21int

Three of these deserve real explanation rather than a table row.

/ always produces a float

Even when the division comes out even. 6 / 2 is 3.0, not 3. If you needed a whole number — say, to count something — you have quietly ended up with a float, and that will show up later as 3.0 items in output that should have said 3 items.

// and % are how you divide things into whole groups

// gives the whole number of times one value fits into another, discarding any remainder. % gives what is left over. Together they answer a question that appears constantly in real logistics and inventory code: how many full boxes, and how many left over?

units      = 47
box_size   = 12

full_boxes = units // box_size
leftover   = units %  box_size

print(full_boxes, leftover)
3 11

Three full boxes of twelve is 36 units, leaving 11. Note // discards the remainder rather than rounding: 47 // 12 is 3, even though 47 / 12 is about 3.92.

Order of operations

Python follows standard mathematical precedence: ** first, then *, /, //, %, then + and -. Equal precedence evaluates left to right. Parentheses override everything.

print(4.99 + 4.99 * 0.20)      # tax on the cost, then added
print((4.99 + 4.99) * 0.20)    # tax on double the cost — different thing
5.988 1.996

Use parentheses whenever the grouping is not instantly obvious to a reader, even where they are technically unnecessary. Being right is not enough; being unambiguously right matters in code others maintain.

Augmented assignment

total = total + 5 — take the current value of total, add 5, rebind total to the result — is common enough to have a shorthand:

total = 10.0
total += 5.0     # same as: total = total + 5.0
total *= 2       # same as: total = total * 2
print(total)
30.0

The forms -=, /=, //=, %=, **= all exist and work the same way.

7. The float problem you will otherwise hit blind

Run this:

print(0.1 + 0.2)
0.30000000000000004

This is not a bug in Python, and it is not something you can configure away. A float is stored in binary, and just as 1⁄3 cannot be written exactly in decimal (0.333… forever), values like 0.1 cannot be written exactly in binary. What gets stored is the closest representable value, and the tiny errors accumulate.

The consequence for the kind of code in this chapter: never trust a raw float for a displayed price. A computed total of 17.850000000000001 must not reach a customer. You control this with rounding and formatting, both covered next.

Deferred, deliberately Real financial systems generally do not use float for money at all — they use Python's decimal.Decimal type, which stores decimal digits exactly, or store amounts as integer counts of pennies. Both are the correct professional answer and both are taught later, once modules and integer arithmetic patterns are properly established. For now, float plus disciplined rounding is what you have, and knowing why it is a compromise is the point of this section.

8. Converting between types

Data arriving from the outside world — a file, a form, a supplier feed — arrives as text. Converting it is a daily task.

Definition

int(x), float(x), str(x) are built-in functions that each take a value and return a new value of that type. They do not modify x — nothing in Python modifies a number or a string in place. You must use the returned value, usually by assigning it to a name.

raw_cost = "4.99"          # as it arrived from the feed: text
cost     = float(raw_cost)  # now a number we can compute with

print(type(raw_cost), type(cost))
print(cost * 2)
<class 'str'> <class 'float'> 9.98

The behaviours worth knowing before they bite:

  • int("7") → 7. But int("7.5") fails with a ValueError — int will not silently discard a fractional part from text. Convert to float first, then to int.
  • int(7.9) → 7. Converting a float to int truncates toward zero; it does not round. int(-7.9) → -7.
  • float("4.99") → 4.99. float("abc") → ValueError.
  • str(4.99) → "4.99". This always works, for any value.

Rounding properly

Definition

round(x, n) is a built-in function taking a number x and an optional number of decimal places n, returning a new number rounded to that many places. With n omitted it rounds to a whole number and returns an int. With n given it returns a float.

print(round(17.856, 2))
print(round(17.856))
print(round(2.5))
print(round(3.5))
17.86 18 2 4

Those last two are not typos. Python uses banker's rounding: an exact half rounds to the nearest even number, so 2.5 → 2 and 3.5 → 4. This exists because always rounding halves upward introduces a systematic upward bias across many values — a genuine problem in financial and statistical work. It is standard, correct, and surprising the first time.

9. Strings and building output

A str is written between single quotes '…' or double quotes "…" — Python treats them identically. Pick one and be consistent; use the other when the text itself contains a quote:

note = "Supplier's reference"   # apostrophe inside, so use double quotes

Concatenation

+ between two strings joins them. Between a string and a number it raises TypeError — Python refuses to guess what you meant:

name = "Blue Mug"
print("Product: " + name)
print("Cost: " + 4.99)     # TypeError
Product: Blue Mug TypeError: can only concatenate str (not "float") to str

You could fix that with str(4.99). Don't — there is a far better tool.

f-strings

Definition

An f-string is a string literal prefixed with the letter f, in which any expression written between braces { and } is evaluated and its result inserted into the text. It is the standard, idiomatic way to build text from values in modern Python.

name = "Blue Mug"
cost = 4.99
qty  = 3

print(f"{name} x{qty} at £{cost}")
print(f"Line total: £{cost * qty}")
Blue Mug x3 at £4.99 Line total: £14.969999999999999

Note two things. First, no str() conversion was needed — the f-string handles it. Second, arbitrary expressions work inside the braces, not just names: {cost * qty} did real arithmetic. And third — the float problem from §7 arrived exactly as promised.

Format specifiers: fixing that output

Inside the braces you may add a colon followed by a format specifier controlling how the value is rendered:

cost = 4.99
qty  = 3

print(f"Line total: £{cost * qty:.2f}")
Line total: £14.97

The specifier .2f means: render as a fixed-point decimal with exactly 2 places. Crucially it rounds for display and always shows both places — so 5.0 renders as 5.00, which round(5.0, 2) would not give you.

SpecifierMeaningInputOutput
.2fFixed-point, 2 decimals14.969…14.97
.0fFixed-point, no decimals14.9715
,Thousands separators12500001,250,000
,.2fBoth combined1250.51,250.50
>10Right-align in 10 characters"Mug""·······Mug"

(The · above represents a space; it is not printed.) Alignment specifiers are what let you produce column-aligned reports without counting spaces by hand — you will use them in the exercises.

Rounding vs. formatting These are different operations and confusing them causes real bugs. round() changes the value — the number stored is now different. A format specifier changes only the display — the underlying value is untouched. Rule of thumb: format at the moment of display; round only when the rounded number is genuinely the value you want to keep computing with.

10. Reading errors

Programs fail. Being able to read the failure is a skill, not an inconvenience, and it is worth learning now rather than by accumulated frustration.

cost = 4.99
print("Total: " + cost)
Traceback (most recent call last): File "/home/mike/pricing.py", line 2, in <module> print("Total: " + cost) ~~~~~~~~~~~^~~~~~ TypeError: can only concatenate str (not "float") to str

Read it bottom-up — the last line is the actual error:

  • TypeError — the category: an operation got a type it cannot work with.
  • The message after the colon says precisely what went wrong.
  • The File …, line 2 line tells you exactly where.

The three you will meet most this chapter:

ErrorMeansTypical cause
NameErrorA name was used that Python does not knowTypo, or using a name before the line that assigns it
TypeErrorAn operation was given the wrong type"text" + 4.99
ValueErrorRight type, but an unusable valueint("abc"), float("")
SyntaxErrorNot valid Python at allUnclosed bracket or quote — check the line above the reported one

Worked examples

Example 1

A single retail price

The problem. The feed gives a wholesale cost of £4.99. Company policy is a 60% markup, then 20% VAT on the marked-up price. Produce the customer-facing price.

Thinking it through before typing. Two sequential percentage operations. "60% markup" means the retail-ex-VAT price is the cost plus 60% of the cost — that is cost * 1.60. Then VAT adds 20% on top of that, not on the original cost: * 1.20. Getting that order wrong is the classic error, and it produces a plausible-looking but wrong number, which is the worst kind.

Each percentage is a multiplier: 60% markup → ×1.60, 20% VAT → ×1.20. Naming the rates rather than writing 1.60 inline matters, because a policy change should be a one-line edit.

# Retail pricing for a single supplier line.
# Feed sends cost in GBP, excluding VAT.

wholesale_cost = 4.99
markup_rate    = 0.60   # 60% margin over cost
vat_rate       = 0.20   # UK standard rate

price_ex_vat = wholesale_cost * (1 + markup_rate)
price_inc_vat = price_ex_vat * (1 + vat_rate)

print(f"Cost:      £{wholesale_cost:.2f}")
print(f"Ex VAT:    £{price_ex_vat:.2f}")
print(f"Inc VAT:   £{price_inc_vat:.2f}")
Cost: £4.99 Ex VAT: £7.98 Inc VAT: £9.58

Why (1 + markup_rate) and not 1.60? Because the name markup_rate = 0.60 reads as "60 percent", which is how the policy is actually written down. Writing 1.60 forces a future reader to reverse-engineer that the 1 is "the original" and the 0.60 is "the markup". Both compute the same number; one of them communicates.

Why format with :.2f rather than round()? The true value of price_inc_vat is 9.58080000000000, and we want the full precision retained in the variable in case anything downstream uses it — but a customer must see £9.58. Formatting at the point of display does exactly that.

Example 2

Shipping bands from a raw feed

The problem. The feed sends weight as text in grams, e.g. "1850". The warehouse packs in cartons holding 4 units. Given an order of 47 units, report: total shipment weight in kilograms, how many full cartons, and how many units are left over.

Thinking it through. Three separate concerns, and each has a trap. The weight arrives as str, so arithmetic on it will fail until converted — that is §8. Grams to kilograms is a division by 1000, which will produce a float (§6). "Full cartons and leftover" is precisely the // and % pair from §6, and using / here would give 11.75 cartons, which is not a thing that exists in a warehouse.

# Warehouse dispatch summary for one order line.

raw_weight_g = "1850"   # arrives from the feed as text
units        = 47
carton_size  = 4

unit_weight_g  = int(raw_weight_g)
total_weight_g = unit_weight_g * units
total_weight_kg = total_weight_g / 1000

full_cartons = units // carton_size
loose_units  = units %  carton_size

print(f"Units:        {units}")
print(f"Total weight: {total_weight_kg:,.2f} kg")
print(f"Full cartons: {full_cartons}")
print(f"Loose units:  {loose_units}")
Units: 47 Total weight: 86.95 kg Full cartons: 11 Loose units: 3

Why int() and not float() for the weight? Because grams from this supplier are always whole numbers — the type should express what the data actually is. If the feed could send "1850.5", int() would raise ValueError and float() would be correct. Choosing deliberately, rather than reaching for whichever works, is the habit being built here.

Why ,.2f on the weight? The comma adds thousands separators. At 86.95 kg it changes nothing — but this same line will one day run on an order of 40,000 units, and 34,225.00 kg is readable where 34225.0 is not. Formatting for the data you will eventually have, not just today's sample, costs nothing here.

Example 3 · integrating

A formatted margin report line

The problem. Produce one aligned line of a report for a product, showing name, quantity, unit price, line total, and the profit margin as a percentage — from raw feed values, some of which are text.

Thinking it through. This pulls in everything: conversion (§8), arithmetic including a division that must not be integer division (§6), the float trap (§7), f-strings with alignment and percentage specifiers (§9). The one genuinely new piece of reasoning is the margin itself.

Margin is profit as a proportion of the selling price — (price - cost) / price — not of the cost. That second version is markup, a different number, and confusing the two is a real and expensive mistake in retail. At a cost of £4.99 and a price of £9.58, margin is about 48% while markup is about 92%. Both are "the profit", and only one answers the question asked.

# One line of the daily margin report.

name         = "Blue Mug"
raw_cost     = "4.99"      # text, from the feed
raw_qty      = "3"         # text, from the feed
retail_price = 9.58

cost  = float(raw_cost)
qty   = int(raw_qty)

line_total   = retail_price * qty
profit_each  = retail_price - cost
margin       = profit_each / retail_price   # of PRICE, not of cost

print(f"{name:<14}{qty:>4}{retail_price:>10.2f}{line_total:>10.2f}{margin:>9.1%}")
Blue Mug 3 9.58 28.74 47.9%

Reading that final f-string carefully, because it is dense and every part is doing work:

  • {name:<14} — left-align the name in a 14-character column. Left for text, because ragged-right text is what the eye expects.
  • {qty:>4} — right-align the quantity in 4 characters. Right for numbers, so digits line up by place value.
  • {retail_price:>10.2f} — two specifiers combined: right-align in 10 characters, and render as fixed-point with 2 decimals.
  • {margin:>9.1%} — the % multiplies by 100 and appends the sign, so 0.4791… becomes 47.9%. Doing the ×100 by hand and appending "%" manually would be more code and easier to get wrong.

Why no separators between the braces? Because the width specifiers already create the spacing. Adding spaces as well would double-space the columns and break the alignment you just asked for.

What this chapter established

  • A program is a .py file read top to bottom by the python3 interpreter.
  • print() writes values to standard output; type() tells you what a value is.
  • Five types: int, float, str, bool, NoneType — and 4.99 is not "4.99".
  • A name is a label bound to a value, not a container; rebinding moves the label.
  • Arithmetic operators, with / always producing a float and ///% answering "how many whole, how many left".
  • Floats are approximate; round or format before anything reaches a human.
  • int(), float(), str(), round() convert; f-strings with format specifiers display.
  • Tracebacks are read bottom-up.
